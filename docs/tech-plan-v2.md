# 技术方案 v2 — 北极星：询盘（A）+ 信任（B）

日期：2026-09-10 ｜ 取代：CEO 计划 2026-09-10-phase1-backend-launch.md 中的技术选型部分
输入：CEO 评审 13 决策点 + 外部评审 10 发现 + 用户北极星确认（A+B）

## 0. 北极星与决策过滤器

```
目标 A：每月稳定高质量询盘（WhatsApp/邮箱留资）
目标 B：海外买家看完网站 → "这家是正规工厂" → 签单率提升
```

每个技术项按此过滤：
- **直接服务 A/B** → 做，且做到位
- **间接服务**（让 A/B 更好）→ 做最小版
- **不服务**（纯技术优雅/未来扩展）→ 砍掉或推迟

## 1. 与 v1 的关键差异（10 条）

| # | v1（原计划） | v2（本方案） | 理由（A/B 关联） |
|---|-------------|-------------|------------------|
| 1 | 域名暂缓，CF 迁移排最后 | **域名+CF Pages 迁移是第 0 步** | B：可记忆域名和自有域是信任地基；SEO 资产从注册日起算（外部评审#4） |
| 2 | Router→Harness→后置校验全管线 | **阶段一无 Router**（架构文档本意）；管线 = 检索→Harness→后置校验 | Router 服务阶段二 Agent，纯 Harness 阶段是纯开销；A：每条消息省 1-2s 延迟直接关系询盘体验 |
| 3 | "<1s 首 token" 目标 | 管线砍到 3 步 + **跳过性校验**（高相似度命中免后置校验）+ 前端 fetch 超时处理 | 弱网客户 4-10s 死等 = 流失 = 无询盘（外部评审#2） |
| 4 | 0.75 阈值硬编码 | **阈值=环境变量 + 黄金集强制校准为上线步骤**（命中率≥80% 硬指标） | 未校准阈值 → 上线日兜底率可能 100% → AI 显得蠢 → B 反噬（外部评审#3） |
| 5 | SEO 落地页 ×4-5 优先级中 | **降级为第 4 批**（Alibaba 主渠道 + 站外链惩罚，SEO 是慢变量） | 外部评审#10：第一年流量主路径是规格书/包装/名片二维码 → WhatsApp，不是 Google |
| 6 | WhatsApp 直连=补充按钮 | **WhatsApp 是询盘主通道**：浮动按钮 + 每页常驻 + 预填消息（含来源页） | A：中东/东南亚买家最熟通道；表单是次选 |
| 7 | 表单收集 KV+飞书 | 保留但简化：WhatsApp 优先，表单兜底；**飞书通知+邮件双通道**（凭证已有） | A：询盘响应时效是转化生死线 |
| 8 | D1 全量对话存档+dashboard | **埋点只存聚合**（route/score/fallback/页面），**不存对话全文**；无独立 dashboard（CF 控制台看表） | 外部评审#9：PII 存储与隐私政策矛盾；最小版够用（兜底率可算） |
| 9 | KV 限流 | **Workers Rate Limiting binding**（原子）做 IP 限流，KV 只存日计数 | 外部评审#7：KV 最终一致性可被分布式刷量绕过；无成本上限下这是唯一防线 |
| 10 | 知识库 40 条+黄金集工具化 | **知识库 40 条是唯一关键路径**；黄金集 50 题由**工程师独立写答案**（非转写者本人），上线前跑一次校准 | 外部评审#5：转写者自测=循环测试测不出事实错误；B：错误答案=信任崩塌 |

## 3. 施工顺序（v2 反转，共 5 批）

**第 0 批：域名+迁移（B 的地基，先于一切后端）**
1. 域名注册（含 motor 关键词短域，备选 3 个）
2. 全站迁 Cloudflare Pages + R2
3. 文档同步：requirements.md §2.5、deployment.md 红线#2 改为 CF 自建（外部评审#4：文档与决策矛盾）
4. 占位符清单确认（WhatsApp 号/地址/邮箱——B 的硬前提）

**第 1 批：询盘通道（A 的最短路径）**
1. WhatsApp 浮动按钮 + 预填消息（含 utm/来源页）
2. /api/inquiry：Turnstile 验证 → KV 存储 → 飞书+邮件通知
3. IP 限流（RL binding）+ 日上限（KV）
4. 隐私政策页 + consent 勾选
5. 业务员 owner 确认（1 工作日首响 SLA）

**第 2 批：知识库（A+B 共同的关键路径，唯一人力瓶颈）**
1. 工程师供料 40 条中文事实（**拿到日期承诺才开工后端**）
2. AI 辅助双语转写（<10 分钟/条）→ 工程师抽检
3. 工程师独立写黄金集 50 题标准答案（非转写者）
4. 素材入库脚本：OpenAI embedding 预计算 → Vectorize

**第 3 批：AI 后端（等知识库就绪）**
1. /api/chat：检索→Harness→后置校验（无 Router）
2. 阈值校准：黄金集跑通，命中率≥80% 才放行（外部评审#3；**升级为硬 gate**，覆盖此前的"宽松 gate"决策——因为宽松 gate 的前提是阈值已知可靠，实际未校准）
3. 前端接通：fetch 超时、typing 态、来源标签渲染（已有）
4. 聚合埋点（route/score/fallback）

**第 4 批：信任放大与慢变量**
1. SEO 落地页 ×4-5（从第 1 批降级至此）
2. Today's workshop snapshot 机制（工厂拍→上传 R2）
3. 视频素材制作排期（概览+5 机位，按编码规范）
